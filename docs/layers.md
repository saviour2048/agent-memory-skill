# 记忆分层模型

> 把「事实」「经历」「步骤」分开存，像人类记忆一样分层；用状态管理生命周期，只增不删。

## 为什么分层

把所有笔记塞进一个目录，会出现三个问题：

1. **找不到**：稳定事实和一次事故的完整日志混在一起，索引越来越长。
2. **不敢删**：旧结论还有证据价值，删了就没法回溯。
3. **会漂移**：同一规则抄成多份，改一处忘一处。

分层后：事实保持短小、经历保留证据、步骤复用为技能；旧版降级而不删除。

## 三层

| 层 | 模拟人类记忆 | 放什么 | 落到哪 |
|---|---|---|---|
| **语义记忆** semantic | 事实 | 稳定事实、偏好、规则、环境结论 | `memory/<项目键>/<主题>.md` |
| **情景记忆** episodic | 经历 | 一次事故、完整排障、发布来龙去脉 | 项目 handoff；Active 只留结论，过程进 History |
| **程序性记忆** procedural | 技能 | 可重复步骤、检查清单 | `skills/<name>/SKILL.md` |

判断口诀：**事实写语义、故事写情景、步骤写技能。**

### 怎么选层（例子）

| 你得到的 | 放哪 |
|---|---|
| 「这个项目用 xcodegen 生成工程」 | 语义（主题文件） |
| 「今天 CI 挂了 40 分钟，根因是缓存了旧工程文件」 | 情景（事故 handoff，过程进 History） |
| 「发版前必须跑 build + notarize + 校验」 | 程序性（Skill） |

事故的**教训**会升格成语义记忆；事故的**过程与证据**留在情景记忆。

## 索引：MEMORY.md

每个项目键目录一份索引，分两个区：

- **Active**：当前仍有效的事实与结论（默认只读这个区）。
- **History**：已失效/已归档的过程与证据，只在追查历史时读。

索引条目 = 链接 + 约 80–120 汉字摘要。索引负责「发现」，主题文件负责细节。

## 生命周期

| status | 含义 | 读取规则 |
|---|---|---|
| `active` | 当前有效 | 正常读取 |
| `consolidated` | 已合并进别处 | 改读 `consolidated_into` |
| `superseded` | 被新版取代 | 改读 `superseded_by` |
| `archived` | 整体归档 | 正常使用时不读 |
| `historical_detail` | 仅作历史证据 | 只当证据，不当规则 |

旧版本降级 + 移入 History，**永不物理删除**。

## 读写规则

**写**：

1. 先搜重：已有同类当前记忆就更新原文件，不新增重复文件。
2. 选层（见上表）。
3. 主题文件用 kebab-case；frontmatter 至少 `name`、`description`、`metadata.type`、
   `modified`、`status: active`。
4. 在 `MEMORY.md` 的 Active 区追加链接 + 80–120 字摘要；旧版降级移入 History。
5. 全局偏好写 `-HOME/`；机密/账户数据只进私有仓库。

**读**：

1. 先读项目 `MEMORY.md` 索引，再按需读主题文件，不要一次全读。
2. 有 Active/History 分区时默认只读 Active。
3. 每个任务默认读当前项目索引 + 最多 5–7 条相关记忆。
4. 命中文件的 `status` 不是 active 时按上表跳转。
5. 记忆里的环境信息（路径、设备、网络、版本）可能过时，依赖前在当前机器验证。

## 冗余审查

- 同一规则只保留一个现行入口；重复的项目案例标 `consolidated` 留 History。
- 索引摘要不算重复：索引负责发现、主题文件负责细节、Skill 负责流程。
- 历史证据不因「重复结论」删除：不同事故得出同一教训时，归到同一现行入口，原始证据保留。
- 定期检查：内容完全相同的文件、未进索引的 Active、坏链、缺 frontmatter 的文件。
  脚本：`node scripts/memory.mjs lint`。
